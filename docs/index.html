Why Cache-Augmented Generation Matters

~31%
of real-world LLM queries are repetitions
Analysis of ChatGPT conversation logs — nearly one third of user queries are semantically similar to previously submitted questions.
Gill et al., MeanCache: User-Centric Semantic Caching for LLM Web Services, IEEE IPDPS 2025 — Figure 1

In a production LLM service, 3 out of every 10 API calls could be served from a cache — saving compute, money, and latency — without the user noticing. A semantic cache checks whether a similar question was already answered before running the full pipeline.

The Problem

Classic RAG pays the full cost — embedding, vector search, and LLM generation — on every query. Repeated questions recompute identical work. At scale: thousands of wasted GPU-hours and dollars.

The CAG Fix

Insert a semantic cache between user and LLM. Hit: return cached answer instantly (~0.5s). Miss: run full RAG, store result for next time. Same answer quality, fraction of the cost.

How CAG Works
ⓘ Why Nemotron Nano 9B? We deliberately use a small, efficient open model via OpenRouter. A frontier model would answer many AWS questions from its training data alone — making retrieval irrelevant. We want a model that must rely on the retrieved chunks, so the benchmark measures retrieval quality, not model memorization.

Key Concepts

A quick glossary for the terms used across these pages and the benchmark report.

Embedding
A list of numbers that captures the meaning of a piece of text. Similar meanings land near each other. We use OpenAI text-embedding-3-small at 512 dimensions.
Vector search
Finding the stored vectors closest to a query vector, ranked by cosine similarity, instead of matching keywords.
Top-K
The K most similar document chunks returned by the search. This lab retrieves K = 5.
Cosine similarity
How aligned two vectors are, from 0 to 1. Computed as 1 − cosine_distance; 1.0 means identical direction.
Semantic cache
A store of past question → answer pairs keyed by embedding. A new query that is close enough to a stored one is served instantly.
Similarity threshold
The minimum cosine similarity for a cache hit. We operate at 0.96 to keep false positives at zero.
HNSW
Hierarchical Navigable Small World, a graph index for fast approximate nearest-neighbor search. Used by both Redis and Qdrant here.
TTL
Time-to-live: how long a cached answer stays valid before it expires and the question is recomputed.
p50 / p95 latency
The median and 95th-percentile response time. p95 exposes the slow tail that an average would hide.
Cache hit rate
The fraction of queries answered from the cache without running retrieval or generation.
False positive
A cache hit that returns an answer belonging to a different question. We detect these by comparing the stored source_id.
Judge score
A 0 or 1 correctness verdict from a separate LLM judge, kept independent of the model being tested to avoid self-grading bias.

Why I Built This

I was curious about a new approach to RAG called CAG — Cache-Augmented Generation. It adds a caching layer between the LLM and retrieval. As a system architect, I see it the same way we place Redis between an app server and PostgreSQL: a buffer that absorbs repeated reads and serves responses faster. When ~31% of real-world LLM queries are repeats, that's a massive opportunity.

This project was sparked by signals converging from the research community and practitioners:

▶ YouTube video 𝕏 @akshay_pachaar 𝕏 @techNmak 📖 Don't Do RAG 📖 MeanCache

This lab is my playground to test these ideas rigorously — comparing architectures side-by-side on the same dataset, measuring everything that matters.

Run It Yourself

git clone https://github.com/mouadja02/cag-lab.git
cd cag-lab
pip install -e .
pip install pyarrow huggingface_hub     # for vector DB setup
docker compose up -d                    # Redis + Qdrant
python scripts/setup_vectordb.py        # downloads 89k vectors from HuggingFace (mouadja/aws-docs)
cag-lab run --config configs/experiments/rag_baseline.yaml
cag-lab run --config configs/experiments/semantic_cache.yaml
python scripts/generate_comparison_report.py --auto
